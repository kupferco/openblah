# Spike T8: multi-participant agent

Status: spike, code under `packages/agent/src/group/`. Answers the "biggest Verify" in `docs/plan.md` section 2.3. All results below come from offline runs with scripted STT unless marked **not measured**.

## Question

Can one agent session listen to several humans in one LiveKit room, with a speaker-tagged transcript, and decide when to speak?

## What LiveKit Agents JS 1.10 supports

Checked in `@livekit/agents@1.10.0` (the version T4 uses):

- `AgentSession` / `RoomIO` link to **one** participant. `RoomIO` has `linkedParticipant` and `setParticipant(identity | null)`; only that participant's audio feeds the session's STT and turn detector. Switching the linked participant is possible, but there is no API to listen to several at once.
- The building blocks are public and reusable on their own: `stt.STT.stream()` returns a `SpeechStream` with `pushFrame`, `flush`, `endInput`, and `llm.LLM.chat()` is independent of the session.
- Conclusion: **the built-in session cannot do group listening; we build our own** on those primitives. The spike does exactly that, with no change to the T4 single-user pipeline.

## What was built (`packages/agent/src/group/`)

| File                        | Role                                                                                                                                                                    |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session.ts` `GroupSession` | One VAD gate and one recogniser per human track; merges finished turns; runs the classifier per turn; logs one JSON line per decision (`group.decision`).               |
| `vad-gate.ts`               | Gate in front of STT: pre-roll, hangover, savings stats. Energy based here (deterministic, offline). Live it takes a Silero check through the `isSpeech` option.        |
| `transcript.ts`             | Merged transcript ordered by turn end, formatted `[Penelope]: ...`.                                                                                                     |
| `addressing.ts`             | Rules for who a turn is for, names from config (never hard-coded). Treats "Penelope, what do you think?" as addressed to Penelope.                                      |
| `classifier.ts`             | "Should I speak?": rules first, then a small model through `LlmProvider` for ambiguous turns. Output `speak` or `stay_quiet` plus a reason. Failure means `stay_quiet`. |
| `recognizers.ts`            | `sttRecognizerFactory(SttProvider)` for live (one `SpeechStream` per track) and `scriptedRecognizerFactory` for offline replay.                                         |
| `fixtures.ts`, `replay.ts`  | Six scenarios (English and Portuguese), WAV generator, replay of one WAV per participant on a shared audio clock.                                                       |
| `cli.ts`                    | `group:fixtures`, `group:replay`, `group:eval`.                                                                                                                         |

Run (from the repo root, after `pnpm install`):

```
pnpm --filter @openblah/agent group:replay          # transcript and decisions for all scenarios
pnpm --filter @openblah/agent group:eval            # pass/fail per scenario, exit 1 on a miss
GEMINI_API_KEY=... pnpm --filter @openblah/agent group:eval   # adds the model for ambiguous turns
```

## Fixtures: what they are, and are not

The scenarios cover "addressed by name", "humans talking to each other", "opinion requested", a vocative to another human ("Penelope, what do you think?"), in English and Portuguese, with two or three participants.

**Honest limit:** no TTS key or network was available in the coding session, so the WAVs are deterministic speech-like tones (one voiced burst per word, silence between turns), generated by `fixtures.ts`. They exercise the gate, per-track streams, merge and classifier. They do **not** contain intelligible speech, so replay uses a scripted recogniser that emits each scripted line when the gate closes. Recognition quality (Deepgram on English and pt-BR) is **not measured**. To replace the tones with real speech: record WAVs as `fixtures/<scenario>/<Name>.wav` (16 kHz mono) or synthesise them with the Cartesia provider, then run `group:replay --real-stt` with `DEEPGRAM_API_KEY`. The WAVs are generated on demand and not committed (about 1 MB per scenario).

## Results

- All six scenarios give the expected decision for the last human turn (`group:eval`: 6/6), using **rules only**. The model is called only for turns the rules cannot settle (a mid-sentence mention, an opinion cue with no name, a follow-up right after the agent spoke).
- The speaker-tagged transcript comes out in turn order for two and three participants.
- A "speak" decision carries `earliestSpeakMs`: the end of the last human speech on any track plus 1 s, so the agent does not talk over two humans (plan 2.4; the field test says 1 to 2 s was too short, so T9 should make this configurable and test longer).
- Gate savings in the fixtures are 34 to 100 % of audio (per track) kept out of STT. Real rooms with talkative people will save less; a track that is silent costs nothing.
- **Not measured:** the model classifier's accuracy (needs `GEMINI_API_KEY`; `group:eval` will include it when set), real STT quality, end-to-end latency, and real-time behaviour with live LiveKit tracks.

## STT cost per track

Deepgram bills streaming audio by the second sent. Pay-as-you-go list prices for Nova-3 were about 0.46 USD per hour (English) and 0.55 USD per hour (multilingual) when this was written from memory: **verify on deepgram.com before relying on them**.

- Without a gate, a 3-human call costs 3 tracks x call length, even while only one person talks.
- With the gate, each track costs only its speech plus pre-roll and hangover. If people speak 30 to 40 % of the time each, the 3-track cost is about 1 to 1.2 times the call length instead of 3 times, roughly 0.55 to 0.66 USD per hour of multilingual call instead of 1.65 USD. The classifier adds one small-model call for a minority of turns.

## Recommended structure for T9

1. Keep `GroupSession` as the Listening and Facilitating engine and `AgentSession` (T4) for Direct mode. Do not try to make one `AgentSession` hear several people.
2. In the worker, subscribe to each remote human audio track (`RoomEvent.TrackSubscribed`), create a `RecognizerFactory` from `defaultProviders().stt`, and feed frames to `GroupSession.pushAudio`. Replace the energy gate by Silero through `VadGateOptions.isSpeech`. Add/remove participants on join and leave.
3. When the classifier says `speak`, wait until `earliestSpeakMs` has passed with no new human speech, then generate the reply with the merged transcript in the prompt and play it with TTS through a `Room` audio source. This path (own LLM call and TTS, not `AgentSession.say`) needs to be built; it was **not** spiked. Barge-in then has to be implemented on that path too.
4. Add the agent's own spoken lines with `addAgentLine` so "opinion right after the agent spoke" works. In the spike the lines come from the fixture script.
5. T9 adds modes, name from room config, the mute state, notes, the action list and the summary. The classifier needs the mode as an input (Listening: only addressed or opinion requested; Facilitating: also the facilitation rules).
6. Run the classifier eval with the real model on English and Portuguese recordings before tuning the rules.

## Open points

- STT per track means one WebSocket per human; check Deepgram concurrency limits on the free tier for 4 humans.
- Overlapping speech: each track is transcribed alone, so overlapped words are not lost, but turn order near overlaps depends on the track's turn end time.
- Language: `detectLanguage` (word lists from T4) tags each turn; per-track STT language settings can follow later.
